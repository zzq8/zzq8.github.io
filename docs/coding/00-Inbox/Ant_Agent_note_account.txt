## 单Agent框架：ReAct 范式
### 是什么
是经典的 Agent 范式

ReAct介绍:[ReAct 框架 – Nextra](https://www.promptingguide.ai/zh/techniques/react.zh)

+ ReAct (Reasoning and Acting) 是一种 Agent 的提示方法，主要特点是结合了思维链（Chain of Thought）和行动执行。  
ReAct 是 LangChain 中最常用的 Agent 范式之一。

```javascript
不完全相同。虽然它们都是提示方法（Prompting Methods），但有明显区别：

Chain of Thought (CoT):
- 专注于思维推理过程
- 通过中间步骤展示推理链
- 主要用于解决推理类问题
- 输出形式：思维过程 -> 最终答案

ReAct:
- 结合了推理和行动
- 包含工具使用和环境交互
- 能执行实际操作并获取反馈
- 输出形式：思考 -> 行动 -> 观察 -> 新思考 -> ...

举例说明：

CoT示例（数学问题）：
```
问题：如果苹果3个5元，买12个苹果需要多少钱？
思考：
1. 3个苹果是5元
2. 12个苹果是3个的4倍
3. 所以价格也是5元的4倍
答案：20元
```

ReAct示例（查询任务）：
```
问题：查询今天北京的天气并建议是否带伞
思考：需要查询北京天气信息
行动：调用天气API查询北京天气
观察：北京今天多云，降水概率60%
思考：降水概率较高
行动：生成建议
回答：建议带伞，因为今天降水概率较高
```

从你之前分享的表格也可以看出，它们是被分开列举的不同方法，而且组合使用（如 CoT-SC → ReAct）能获得更好的性能。
```



> 好处：**经过一些微调后表现会非常明显地提升**
>

LLM Agent 局限性

+ 依赖于LLM：Agent的所有的衍生技术都严重依赖于LLM的能力，所以一个Agents的好坏，也要看这个LLM优化的是否到位。
+ RT&资源：一般Agent作为一个Controller，需要多次运行和与外界进行交互，本身LLM的模型消耗资源就很大，因此一般Agents的系统运行效率都不会太高，输出Token数过多的情况，RT会比较高
+ Token Lengths长度限制：另一个通用的问题就是LLM的输入会有长度限制，一般是2048，4096等等，总之都是有限的，我们在做Agent的轮次就不会太长，这会限制Agents来解决更复杂问题的能力。
+ 不稳定性：总体上，LLM的输出还是不可控的，会在有时候不遵循instruction，然后开始胡说八道的情况，这会导致Agents的运行出现异常。

# ✨ RAG:增强检索生成
> [https://waytoagi.feishu.cn/wiki/WiAwwqSfYiT8sKkYU33c7FMpnvh](https://waytoagi.feishu.cn/wiki/WiAwwqSfYiT8sKkYU33c7FMpnvh)
>



> <font style="color:rgb(51, 65, 85);">简单来说，系统根据用户的输入查询相关文档，然后将这些文档和一个提示语结合起来，交给模型生成最终的回答</font>
>



> ✨ [素材归档](https://aliyuque.antfin.com/gd/dit/qsavxb4hagogcoip#0UJbd)  --->  <font style="background-color:#FBDE28;">知识库系分</font>
>
> <font style="color:rgb(6, 6, 7);">RAG，即Retrieval-Augmented Generation，是一种结合了检索（Retrieval）和生成（Generation）的机器学习模型。在RAG模型中，"知识库"通常指的是一个预先构建好的数据集合，这个集合包含了大量的信息或数据，可以是文本、图像或其他形式的数据。知识库在RAG模型中的作用是提供相关信息，以增强模型的生成能力。</font>
>
> **<font style="color:rgb(6, 6, 7);">具体来说，在RAG模型中，当模型接收到一个输入（如问题或指令）时，它会首先使用检索机制从知识库中检索出与输入相关的信息。然后，这些检索到的信息会被用作上下文，与原始输入一起输入到生成模型中，以生成更加准确和丰富的输出。</font>**
>
> <font style="color:rgb(6, 6, 7);">知识库可以是静态的，也可以是动态更新的，这取决于具体的应用场景和需求。知识库的选择和构建对于RAG模型的性能有很大的影响，因为它直接影响到检索阶段的效果。一个高质量的知识库可以提供更准确、更全面的信息，从而提高生成模型的输出质量。</font>
>

![](https://i-blog.csdnimg.cn/img_convert/aad0a347b1cc0edb1cbeac8b02bec035.png)

<font style="color:rgb(6, 6, 7);"></font>



> RAG 2020年Facebook提出来的，解决模型训练中需要依赖外部支持的问题
>
> **检索**增强**生成**（Retrieval-Augmented Generation,RAG）指的是在LLM回答问题之前从外部知识库中检索相关信息，**<font style="color:#DF2A3F;">RAG有效地将LLM的参数化知识与非参数化的外部知识库结合起来</font>**，使其成为实现大型语言模型的最重要方法之一

> QQ 和 QA 匹配
>

让我通过具体例子解释在向量知识库中 QA 和 QQ 召回的区别：

QA召回例子：

```plain
用户问题：
"如何配置企业微信支付？"

向量知识库中存储的QA对：
Q: "如何配置企业微信支付？"
A: "1. 登录企业微信管理后台
    2. 进入支付管理页面
    3. 填写商户号和API密钥
    4. 配置回调地址
    5. 测试支付功能"

匹配过程：
系统直接匹配问题向量，返回对应的完整答案内容
```

QQ召回例子：

```plain
用户问题：
"如何配置企业微信支付？"

向量知识库中的相似问题：
- "怎么设置企业微信商户支付？"
- "企业微信支付配置流程是什么？"
- "微信支付商户号怎么配置到企业微信？"
- "企业微信支付密钥在哪里设置？"

匹配过程：
系统返回相似问题列表，用户可以选择最接近自己意图的问题
```

主要区别：

1. **<font style="color:#DF2A3F;">QA直接给出答案，QQ 提供相似问题</font>**
2. QA 适合精确匹配场景，QQ 适合模糊查询
3. QA 强调答案的准确性，QQ 强调问题的相关性

在实际应用中，两种方式经常结合使用：

1. 先用 QQ 找到最相似的问题
2. 再用 QA 返回对应的标准答案

这样可以提高系统的召回率和准确率。

## ✨ Agent架构设计
### Agent设计模式
Agent的几种设计模式：

![画板](https://i-blog.csdnimg.cn/img_convert/d03eef831d9cf5ade6ec7a46b99e301f.jpeg)

1. ReAct（Reasoning-Acting）：思考-行动-观察
2. REWOO(Reason WithOut Observation)：加入Plan。计划-循环执行Task-总结
3. PE（Plan & Execute）：加入RePlan。计划-执行Task-RePlan
4. LLM Compiler：加入并行执行。计划-并行执行Task-RePlan
5. PEER：Plan-Execute-Express-Review
6. Basic Reflection：生成器-评估器模型，生成器生成结果，评估器评估结果反馈生成器
7. Self-Discover：边推理边思考。
    1. 论文：[https://arxiv.org/pdf/2402.03620](https://arxiv.org/pdf/2402.03620)
8. Reflection：加入强化学习模型。
9. LATS（Language Agent Tree Search）加入搜索树与PE思想。



### Agent协作方式


#### 协作方式
![画板](https://i-blog.csdnimg.cn/img_convert/b5b847d58a66c09e19754b9b6ac6bfb1.jpeg)



总结下来Agent的协作方式有：

1. **Sequential**：这是一种多个Agent串行的方式，这种方式预计会成为主流配置的方式之一。
2. **Async**：这是一种Agent能够异步执行的方式，这种方式通常用来处理异步任务，同时这种方式难以监控，比较消耗性能资源，技术上一定要有防止资源耗尽的手段。
3. **Supervisor**：这是一种层级结构的协作方式，同时这也可以成为中心化架构配置的一种方式，这种方式预计也会成为主流配置的方式之一。
4. **Chat Group**：这是一种去中心化的方式，后续也会演变出比较多的变体，比如：去中心化共同协作完成任务、任务抢答、消息通知等等。
